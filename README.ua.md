# s3d Smart Autopilot

[English](README.md) | [Українська] | [Русский](README.ru.md)

Форк [SiaFoundation/s3d](https://github.com/SiaFoundation/s3d) — S3-сумісного шлюзу для Sia, створений для спільної роботи з **indexd Smart Autopilot**.

> **Статус: alpha.** Цей випуск перевірено лише на одному вузлі Windows. API та поведінка можуть змінюватися між alpha-випусками.

## Архітектура

```text
S3-клієнт
   |
   v
s3d Smart Autopilot
   |  отримує політику надлишковості та ліміти передавання
   v
indexd Smart Autopilot
   |  надає політику облікового запису та керування розміщенням
   v
Хости Sia
```

Відповідальність між компонентами розділена навмисно. `indexd` надає значення політики та лімітів передавання, а `s3d` використовує їх для перевірки схеми erasure coding і керування передаваннями. Ця alpha-версія не реалізує всередині `s3d` повну систему оцінювання хостів або вибору портфеля хостів.

## Випуск

| Параметр | Значення |
|---|---|
| Випуск | `v0.1.0-alpha.1` |
| Версія збірки | `v0.2.1-a538024` |
| Базова версія upstream | `s3d v0.2.1` |
| Сумісний індексатор | `indexd Smart Autopilot v0.1.0-alpha.1` (`v0.6.1-9fd0bf52`) |

Для користувацьких політик надлишковості та лімітів передавання використовуйте сумісний випуск `indexd Smart Autopilot`. З upstream-версією `indexd`, яка не повертає значення користувацької політики, застосовується стандартна поведінка.

## Реалізовані можливості

### Політика надлишковості від індексатора

- Під час запуску та кожного циклу завантаження `s3d` читає `redundancyPolicy` з відповіді `GET /account` індексатора.
- Значення `sia.dataShards` і `sia.parityShards` перевіряються відповідно до цієї політики.
- Користувацькі схеми, наприклад 3-of-5 або 10-of-20, можуть використовуватися, якщо це дозволяє політика індексатора.
- Якщо індексатор відхиляє налаштовану схему, завантаження призупиняються з чітким поясненням замість нескінченного циклу повторних спроб. Вони відновлюються, коли політика знову дозволяє цю схему.
- Якщо індексатор не повідомляє користувацьку політику, застосовується стандартна поведінка.

### Ліміти передавання від індексатора

- `s3d` читає `transferLimits` з відповіді `GET /account` індексатора.
- Ліміти завантаження до Sia та скачування з Sia, налаштовані для облікового запису або квоти в `indexd`, застосовуються до активних передавань і оновлюються щохвилини.
- Мережеві ліміти перетворюються на ліміти потоків. Поточне перетворення використовує ліміт upload × K/N та ліміт download ÷ 1.5 як консервативну верхню оцінку.
- Якщо ліміти не передані, додаткове обмеження швидкості не застосовується.

Ліміти передавання є оцінками, а не суворими гарантіями загального мережевого трафіку. Повторні спроби, паралельні запити до повільних шардів і доповнення останнього slab можуть збільшити фактичний трафік.

### Статус і версія

- `s3d status` показує розділи **Redundancy** і **Limits**, зокрема активні значення та їхнє джерело.
- Версія збірки відображається в журналі запуску та команді `s3d version`.
- Версія збірки форка поєднує upstream-версію з коротким хешем коміту форка, наприклад `v0.2.1-a538024`.

## Збирання з вихідного коду

Вимоги:

- Go 1.27
- C toolchain (MinGW-w64) для SQLite
- PowerShell 7
- Сумісний checkout `indexd Smart Autopilot` у сусідньому каталозі `..\indexd`

Запустіть із робочого каталогу s3d:

```powershell
pwsh -File scripts\build-fork.ps1
```

Виконуваний файл буде створено в `dist\s3d-<version>.exe`.

Форк використовує локальну заміну в `go.mod`:

```go
replace go.sia.tech/indexd => ../indexd
```

Перед збиранням розмістіть сумісні робочі репозиторії `s3d` та `indexd` у сусідніх каталогах.

## Оновлення з upstream s3d

1. Спочатку оновіть `indexd`, якщо цього вимагає випуск.
2. Зупиніть `s3d`.
3. Створіть резервну копію каталогу даних s3d. Upstream `s3d v0.2.1` виконує міграцію бази SQLite.
4. Замініть виконуваний файл і запустіть `s3d`. Наявні конфігурація та ключі мають залишитися без змін.
5. Перевірте журнал запуску та виконайте `s3d status`. Зверніть увагу на повідомлення `erasure coding scheme accepted` і `indexer transfer limits`.

Перед оновленням завжди зберігайте резервну копію каталогу даних.

## Відомі обмеження

- Alpha-версію перевірено лише на одному вузлі Windows.
- Ліміти передавання є оцінками. Повторні спроби, паралельні запити до повільних шардів і доповнення останнього slab можуть збільшити фактичний трафік.
- Переміщення або перейменування об'єкта через S3 copy-and-delete може завантажувати дані об'єкта із Sia. Цю поведінку ще не досліджено.

## Напрям розвитку проєкту

Загальна мета Smart Autopilot — зробити рішення щодо зберігання даних налаштовуваними та зрозумілими в усіх компонентах. Напрям розвитку передбачає окремі виміри оцінювання хостів — надійність, продуктивність, ресурси, економіку, заставу/ризик, технічну сумісність і мережеву різноманітність — та розміщення на рівні портфеля замість одного непрозорого бала.

Це цілі проєкту, а не можливості, реалізовані в цій alpha-версії s3d. У цьому випуску `s3d` використовує політики, надані індексатором; повна система оцінювання хостів і вибору портфеля всередині `s3d` не реалізована.
