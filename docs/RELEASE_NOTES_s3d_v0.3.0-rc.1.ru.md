# s3d Smart Autopilot v0.3.0-rc.1

| | |
|---|---|
| Версия сборки | `v0.3.0-rc.1` (commit `446c1b5`) |
| Базовая версия upstream | `s3d v0.2.1` |
| Требуется | `indexd Smart Autopilot v0.3.0-rc.1` для размещения Smart и отчётов о расходах; с upstream indexd используется стандартное поведение |
| Предыдущий выпуск | s3d Smart Autopilot v0.2.0-alpha.1 (`v0.2.1-ba6f8c9`) |

Первый релиз-кандидат форка s3d. Теперь s3d следует режиму Autopilot Mode индексатора: в Smart Active он размещает новые загрузки на хостах с наибольшим Smart Overall и присылает объём каждой успешной передачи, чтобы indexd вёл учёт расходов по хосту.

## Новое

- **Размещение Smart (следует Autopilot Mode индексатора).** Режим и Smart Overall хостов приходят вместе со списком хостов от indexd (обновляется раз в 10 минут). `Original`: порядок хостов прежний. `Smart Shadow`: порядок прежний, порядок, который выбрал бы Smart, только записывается в журнал. `Smart Active`: новые сектора пишутся на хосты с наибольшим Smart Overall, строго по этому порядку (при равных оценках случайно). Хост с недавними отказами пропускается и берётся следующий по порядку; хост без оценки идёт последним. Чтение и скачивание не меняются. indexd без этих полей работает как Original.
- **Собственный `smart-autopilot.log`** рядом с данными s3d. Строка `smart placement mode` пишется, когда режим впервые получен или изменился, а строка `smart placement` на каждую операцию загрузки (режим, slab, шарды, выбранные хосты, хосты, которые выбрал бы Smart, доля совпадения, число хостов без оценки). Одинаковые записи не повторяются; запись пишется не реже раза в 30 минут.
- **Отчёты о расходах на передачи для indexd.** s3d суммирует успешные передачи по хосту и направлению (без фильтра 64 КиБ, который действует для замеров скорости) и раз в минуту отправляет их (`POST /hosts/usage`, пакеты до 1000 записей с идентификатором, повтор с тем же идентификатором; последний отчёт отправляется при остановке). indexd оценивает стоимость по ценам хоста и показывает её на странице Contracts. indexd, не принимающий отчёты (`404`/`405`), определяется один раз, и отправка отключается до перезапуска.
- **`s3d status`**: новый раздел «Host usage» (отправлено, в очереди, отброшено, время последнего успеха).
- Всё из v0.2.0-alpha.1 остаётся: замеры скорости для оценки Performance, политика избыточности и лимиты передачи от индексатора.

## Обновление

1. Сначала обновите indexd до Smart Autopilot v0.3.0-rc.1.
2. Остановите s3d и сделайте резервную копию его каталога данных.
3. Замените исполняемый файл и запустите s3d. Сообщения `erasure coding scheme accepted` и `indexer transfer limits` остаются в журнале; `smart-autopilot.log` появляется, когда впервые получен список хостов.
4. **s3d следует режиму indexd.** Если indexd стоит в Smart Active, новый s3d начнёт размещать по Smart Overall в течение 10 минут. Чтобы сначала понаблюдать, переключите indexd в Smart Shadow до запуска s3d, посмотрите `smart-autopilot.log`, затем включите Smart Active. Аварийный тормоз: Smart Shadow (в пределах 10 минут; идущая загрузка меняется со следующего slab).
5. С indexd, не являющимся форком Smart Autopilot (или более старым), s3d работает как раньше.

## Известные проблемы и примечания

- **Релиз-кандидат.** Проверено на одном узле Windows.
- Режим и оценки обновляются вместе со списком хостов (до 10 минут после изменения).
- В Smart Active порядок строгий, но хост, который только что отказал (в том числе проиграл гонку более быстрому), на время пропускается, поэтому большая параллельная загрузка может распределиться по большему числу хостов, чем лучшие N.
- Отчёты о расходах оценочные: неудавшиеся и прерванные передачи не считаются, а стоимость вычисляет indexd по ценам хостов.
- Замечания предыдущего выпуска остаются в силе: лимиты передачи являются оценкой верхнего предела; перемещение или переименование объекта через S3 copy + delete может скачивать данные объекта из Sia (не исследовано); замеры скорости учитывают только успешные передачи, а скорость скачивания в основном отражает отклик хоста.
- Известные падения тестов: `TestAppConnect` (часовой пояс) и `TestRecoverShardsLateHosts` при параллельной нагрузке (по отдельности проходит).
