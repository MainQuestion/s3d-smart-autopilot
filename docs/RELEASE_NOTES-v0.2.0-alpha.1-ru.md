# s3d Smart Autopilot v0.2.0-alpha.1

Второй alpha-выпуск форка s3d: s3d начинает присылать индексатору замеры скорости передач, из которых indexd считает оценку Performance хостов.

| Параметр | Значение |
|---|---|
| Версия сборки | `v0.2.1-ba6f8c9` |
| Базовая версия upstream | `s3d v0.2.1` |
| Требуется | `indexd Smart Autopilot v0.2.0-alpha.1` (`v0.6.1-7838380a`) для оценки скорости, пользовательской политики и лимитов передачи; с upstream indexd используется стандартное поведение |

## Новое

- **Замеры скорости передач для индексатора.** s3d подписывается на публичные опции SDK `WithUploadProgress` и `WithDownloadProgress` и отправляет в indexd результат каждой успешной передачи шарда: хост, объём и время (`POST /hosts/speed`). По этим замерам indexd считает оценку Performance (скорость) хостов и показывает её на странице Hosts.
- **Передача не замедляется.** Обработчики только кладут замер в очередь (4096 записей) и не ждут ответа индексатора; при переполнении лишние замеры отбрасываются. Отправка идёт в фоне раз в минуту или при накоплении 500 замеров, пачками до 1000; при ошибке сети замеры остаются в буфере (до 5000, лишние старые отбрасываются) и уходят в следующем цикле.
- **Замеры меньше 64 КиБ не отправляются.** Короткие чтения показывают отклик хоста, а не скорость, поэтому они пропускаются на стороне s3d.
- **Совместимость с upstream indexd.** Если индексатор не принимает замеры (ответ `404` или `405`), s3d отключает отправку до перезапуска и больше запросов не шлёт; остальные функции работают как раньше.
- **`s3d status`**: добавлена информация о замерах скорости: сколько отправлено, пропущено (слишком мелкие), отброшено и находится в буфере, время последней успешной отправки; те же данные есть в административной статистике.

## Обновление

1. Сначала обновите `indexd` до `indexd Smart Autopilot v0.2.0-alpha.1`.
2. Остановите `s3d` и создайте резервную копию его каталога данных.
3. Замените исполняемый файл и запустите `s3d`. Сообщения `erasure coding scheme accepted` и `indexer transfer limits` в журнале остаются, как в alpha.1; состояние отправки замеров видно в `s3d status`.
4. Оценка скорости появляется после первых загрузок или скачиваний через s3d и очередного пересчёта в indexd (до 10 минут). Хосты, через которые s3d не передавал данные, остаются с оценкой 1.

## Известные проблемы и примечания

- **Alpha.** Выпуск проверен только на одном узле Windows.
- **Замеры только успешных передач.** Для загрузки учитывается победившая попытка гонки, для скачивания первые успешные шарды, поэтому оценка слегка завышена для медленных хостов (в замер не попадают проигравшие и отменённые попытки и таймауты).
- **Скорость скачивания в основном отражает отклик хоста.** SDK читает часть сектора (около 100 КиБ на шард), поэтому Мбит/с скачивания сравнивают хосты между собой, но не равны пропускной способности канала. Загрузка измеряется по целым секторам.
- **Замеры присылает только s3d этого форка.** Значения передаёт клиент, от подделки они не защищены (indexd проверяет только правдоподобие и размер пакета).
- Лимиты передачи являются оценкой верхнего предела: повторные попытки, параллельные запросы к медленным шардам и дополнение последнего slab могут приводить к дополнительному трафику.
- Перемещение или переименование объекта через S3 copy + delete может скачивать данные объекта из Sia. Это поведение пока не исследовано.
