# s3d Smart Autopilot v0.2.0-alpha.1

Другий alpha-випуск форка s3d: тепер s3d надсилає індексатору вимірювання швидкості передавання, за якими `indexd` розраховує оцінки Performance хостів.

| Параметр | Значення |
|---|---|
| Версія збірки | `v0.2.1-ba6f8c9` |
| Базова версія upstream | `s3d v0.2.1` |
| Потрібен | `indexd Smart Autopilot v0.2.0-alpha.1` (`v0.6.1-7838380a`) для оцінювання швидкості, користувацької політики та лімітів передавання; з upstream indexd застосовується стандартна поведінка |

## Нове

- **Вимірювання швидкості для індексатора.** s3d підписується на публічні опції SDK `WithUploadProgress` і `WithDownloadProgress` та надсилає результат кожного успішного передавання шарда до indexd: хост, обсяг і час (`POST /hosts/speed`). indexd використовує ці вимірювання для розрахунку оцінки Performance хостів і відображає її на сторінці Hosts.
- **Передавання не сповільнюється.** Обробники лише додають вимірювання до черги (4096 записів) і не очікують відповіді індексатора; при переповненні зайві вимірювання відкидаються. Надсилання у фоні виконується раз на хвилину або після накопичення 500 вимірювань, пакетами до 1000. У разі мережевої помилки вимірювання залишаються в буфері (до 5000 записів; зайві старі записи відкидаються) та надсилаються в наступному циклі.
- **Вимірювання менше 64 КіБ не надсилаються.** Короткі читання переважно показують час відгуку хоста, а не пропускну здатність, тому на стороні s3d вони пропускаються.
- **Сумісність з upstream indexd.** Якщо індексатор не приймає вимірювання (`404` або `405`), s3d вимикає надсилання до перезапуску та більше не надсилає запитів; інші функції працюють як раніше.
- **`s3d status`**: додано інформацію про вимірювання швидкості — кількість надісланих, пропущених (занадто малих), відкинутих і буферизованих записів, а також час останнього успішного надсилання; ті самі дані доступні в адміністративній статистиці.

## Оновлення

1. Спочатку оновіть `indexd` до `indexd Smart Autopilot v0.2.0-alpha.1`.
2. Зупиніть `s3d` і створіть резервну копію його каталогу даних.
3. Замініть виконуваний файл і запустіть `s3d`. Повідомлення `erasure coding scheme accepted` та `indexer transfer limits` у журналі залишаються, як в alpha.1; стан надсилання вимірювань видно в `s3d status`.
4. Оцінка швидкості з'являється після перших завантажень або скачувань через s3d та наступного перерахунку в indexd (до 10 хвилин). Хости, через які s3d не передавав дані, залишаються з оцінкою 1.

## Відомі проблеми та примітки

- **Alpha.** Випуск перевірено на одному вузлі Windows.
- **Лише успішні передавання.** Для оцінювання завантаження враховується переможна спроба гонки, для скачування — перші успішні шарди, тому оцінка для повільних хостів може бути дещо завищеною (програні, скасовані спроби та тайм-аути не потрапляють до вимірювання).
- **Швидкість скачування переважно відображає час відгуку.** SDK читає частину сектора (близько 100 КіБ на шард), тому Мбіт/с скачування корисні для порівняння хостів, але не є повною пропускною здатністю каналу. Завантаження вимірюється цілими секторами.
- **Вимірювання надсилає лише s3d цього форка.** Значення передає клієнт, вони не захищені від підробки (indexd перевіряє лише правдоподібність і розмір пакета).
- Ліміти передавання є оцінкою верхньої межі: повторні спроби, паралельні запити до повільних шардів і завершення останнього slab можуть призводити до додаткового трафіку.
- Переміщення або перейменування об'єкта через S3 copy + delete може скачувати дані об'єкта з Sia. Ця поведінка поки не досліджена.
