# s3d v0.3.1-rc.1

**Главное: режимы записи в сеть (в том числе без гонок), параметры буферов и сводки по передачам для indexd.**

Релиз-кандидат (**RC**). Ноябрь 2026. Коммит сборки: `762029b`.

- Основа: официальный s3d (Sia Foundation) и клиентская библиотека `sia-storage-go` (наш форк на коммите `f9961f7`). Это неофициальная сборка, она не связана с Sia Foundation.
- Платформа: Windows (amd64).
- Сводки по передачам принимает наш форк indexd.
- Перед установкой сделайте копию `s3d.exe` и `s3d.yml`.

## Что нового

### Три режима записи в сеть
Выбираются настройками `s3d.yml`, пересборка не нужна.

| Режим | Настройки | Как работает |
|---|---|---|
| **По умолчанию** | (ничего) | как в оригинале: запись с гонками (запасная попытка у другого хоста, если первый медлит) |
| **Без гонок** | `uploadRacing: false` и `uploadAttemptTimeoutSeconds: 30` | шард пишется одному хосту; если он не успел за срок, берётся другой. Нет лишнего трафика на «проигравших» |
| **С ограниченным хеджированием** | `uploadHedgeBudget: 0.05` | дополнительная попытка запускается только для заметно медленных записей: время ожидания берётся из истории записей хоста (оценка Каплана — Мейера), а доля таких попыток ограничена бюджетом (5% первых попыток за минуту) |

В наших измерениях на одном ПК с тремя хостами лучший результат давал режим **без гонок с буфером в 4 слэба**. Результат зависит от ваших хостов и канала, режим стоит подбирать замером.

### Параметры буфера
- `uploadMaxBufferedSlabs` — сколько слэбов одновременно держится в памяти при загрузке: ключевой параметр скорости. Больше — быстрее, но больше памяти и больше одновременной нагрузки на хосты.
- `downloadMaxBufferedChunks` — то же для скачивания.

Пример `s3d.yml` (фрагмент), использованный нами:
```yaml
uploadThreads: 1
uploadRacing: false
uploadAttemptTimeoutSeconds: 30
uploadMaxBufferedSlabs: 4
```

### Сводка по передачам для indexd
s3d считает по каждому хосту и направлению (чтение или запись) попытки и их исходы и присылает indexd сводку раз в минуту:

- попытки (только передачи целых секторов от 4 МиБ; более короткие считаются отдельно в `shortAttempts`);
- проигранные гонки, таймауты, отказы подключения;
- **ответы хоста с ошибкой** (`hostErrors`): хост ответил ошибкой сам («not enough storage», «internal error», «sector not found» и подобные). Ошибки на стороне клиента (неверный запрос, платёж, истёкшие цены) и транспортные сбои сюда не входят.

indexd использует эти данные в отчёте о доле работы хоста и для диагностики. Нагрузка на скорость передачи ничтожна (сотни наносекунд на событие).

### `s3d status`
В выводе появились строки **Attempts counted** и **Host errors** с разбивкой по хостам и направлениям.

### Клиентская библиотека (`sia-storage-go`)
В s3d встроена наша ветка библиотеки с тремя изменениями:

- события попыток передачи (успех, таймаут, отмена, проигрыш, отказ подключения, ошибка хоста) отдаются приложению;
- тип `ConnectError` отличает отказ подключения к хосту от ошибок после соединения;
- доработки загрузки, на которые опираются режимы записи из таблицы выше.

## Обновление

1. Остановите s3d. Скопируйте `s3d.exe` и `s3d.yml`.
2. Замените `s3d.exe` и запустите. Новых обязательных настроек нет, старый `s3d.yml` работает как есть, режим по умолчанию остаётся прежним.
3. Для режима без гонок добавьте `uploadRacing: false` и `uploadAttemptTimeoutSeconds: 30`, перезапустите s3d.
4. Проверьте: `s3d version` и `s3d status`.

**Возврат:** верните прежний `s3d.exe`; новые ключи в `s3d.yml` старая версия может не принять, поэтому уберите их из конфигурации.

## Известные ограничения

- Наши изменения основаны на версии библиотеки `f9961f7`. В новых версиях официальной библиотеки транспортный движок заменён на Rust (`sia-sdk-rs` через cgo), и наши правки на него не переносятся: пока мы остаёмся на этой версии, обновление библиотеки невозможно без переработки.
- Режимы записи подобраны на одной системе из трёх хостов; на других конфигурациях результат может отличаться.
- Проверено на одном Windows-ПК автора.
