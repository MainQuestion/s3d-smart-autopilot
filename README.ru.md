# s3d Smart Autopilot

[English](README.md) | [Українська](README.ua.md) | Русский

Форк [SiaFoundation/s3d](https://github.com/SiaFoundation/s3d) — S3-совместимого шлюза для Sia, созданный для совместной работы с **indexd Smart Autopilot**.

> **Статус: alpha.** Этот выпуск проверен только на одном узле Windows. API и поведение могут меняться между alpha-выпусками.

## Архитектура

```text
S3-клиент
   |
   v
s3d Smart Autopilot
   |  получает политику избыточности и лимиты передачи
   v
indexd Smart Autopilot
   |  предоставляет политику учётной записи и управление размещением
   v
Хосты Sia
```

Ответственность между компонентами разделена намеренно. `indexd` предоставляет значения политики и лимитов передачи, а `s3d` использует их для проверки схемы erasure coding и управления передачами. Полная система оценки хостов и выбора портфеля реализуется на стороне `indexd`; `s3d` отвечает за применение политик и сбор измерений скорости.

## Выпуск

| Параметр | Значение |
|---|---|
| Выпуск | `v0.2.0-alpha.1` |
| Версия сборки | `v0.2.1-ba6f8c9` |
| Базовая версия upstream | `s3d v0.2.1` |
| Совместимый индексатор | `indexd Smart Autopilot v0.2.0-alpha.1` (`v0.6.1-7838380a`) |

Для пользовательских политик избыточности и лимитов передачи используйте совместимый выпуск `indexd Smart Autopilot`. С upstream-версией `indexd`, которая не возвращает значения пользовательской политики, применяется стандартное поведение.

## Реализованные возможности

### Политика избыточности от индексатора

- При запуске и в каждом цикле загрузки `s3d` читает `redundancyPolicy` из ответа `GET /account` индексатора.
- Значения `sia.dataShards` и `sia.parityShards` проверяются в соответствии с этой политикой.
- Пользовательские схемы, например 3-of-5 или 10-of-20, могут использоваться, если это разрешено политикой индексатора.
- Если индексатор отклоняет настроенную схему, загрузки приостанавливаются с понятным объяснением вместо бесконечного цикла повторных попыток. Они возобновляются, когда политика снова разрешает эту схему.
- Если индексатор не сообщает пользовательскую политику, применяется стандартное поведение.

### Лимиты передачи от индексатора

- `s3d` читает `transferLimits` из ответа `GET /account` индексатора.
- Лимиты загрузки в Sia и скачивания из Sia, настроенные для учётной записи или квоты в `indexd`, применяются к активным передачам и обновляются каждую минуту.
- Сетевые лимиты преобразуются в лимиты потоков. Текущее преобразование использует лимит upload × K/N и лимит download ÷ 1.5 как консервативную верхнюю оценку.
- Если лимиты не переданы, дополнительное ограничение скорости не применяется.

Лимиты передачи являются оценками, а не строгими гарантиями общего сетевого трафика. Повторные попытки, параллельные запросы к медленным шардам и дополнение последнего slab могут увеличить фактический трафик.

### Измерения скорости для Performance (G2)

`s3d Smart Autopilot` собирает реальные измерения успешных передач и передаёт их в `indexd`:

- используются публичные SDK callbacks `WithUploadProgress` и `WithDownloadProgress`;
- передаются хост, объём и время передачи через `POST /hosts/speed`;
- обработчики только помещают измерение в очередь и не ждут ответа индексатора;
- отправка выполняется в фоне раз в минуту или при накоплении 500 измерений, пачками до 1000;
- при сетевых ошибках измерения остаются в буфере и отправляются позже;
- измерения меньше 64 КиБ пропускаются;
- `s3d status` показывает отправленные, пропущенные, отброшенные и буферизованные измерения и время последней успешной отправки.

`indexd` использует эти измерения для расчёта **Performance (G2)**.

### Статус и версия

- `s3d status` показывает разделы **Redundancy** и **Limits**, включая действующие значения и их источник.
- Версия сборки отображается в журнале запуска и в команде `s3d version`.
- Версия сборки форка объединяет upstream-версию с коротким хешем коммита форка, например `v0.2.1-ba6f8c9`.

## Сборка из исходного кода

Требования:

- Go 1.27
- C toolchain (MinGW-w64) для SQLite
- PowerShell 7
- Совместимый checkout `indexd Smart Autopilot` в соседнем каталоге `..\indexd`

Запустите из рабочего каталога s3d:

```powershell
pwsh -File scripts\build-fork.ps1
```

Исполняемый файл будет создан в `dist\s3d-<version>.exe`.

Форк использует локальную замену в `go.mod`:

```go
replace go.sia.tech/indexd => ../indexd
```

Перед сборкой разместите совместимые рабочие репозитории `s3d` и `indexd` в соседних каталогах.

## Обновление с upstream s3d

1. Сначала обновите `indexd`, если этого требует выпуск.
2. Остановите `s3d`.
3. Создайте резервную копию каталога данных s3d. Upstream `s3d v0.2.1` выполняет миграцию базы SQLite.
4. Замените исполняемый файл и запустите `s3d`. Существующие конфигурация и ключи должны остаться без изменений.
5. Проверьте журнал запуска и выполните `s3d status`. Обратите внимание на сообщения `erasure coding scheme accepted` и `indexer transfer limits`.

Перед обновлением всегда сохраняйте резервную копию каталога данных.

## Известные ограничения

- Alpha-версия проверена только на одном узле Windows.
- Лимиты передачи являются оценками. Повторные попытки, параллельные запросы к медленным шардам и дополнение последнего slab могут увеличить фактический трафик.
- Перемещение или переименование объекта через S3 copy-and-delete может скачивать данные объекта из Sia. Это поведение пока не исследовано.

## Направление развития проекта

Общая цель Smart Autopilot — сделать решения по хранению данных настраиваемыми и понятными во всех компонентах. Направление развития предусматривает отдельные измерения оценки хостов — надёжность, производительность, ресурсы, экономику, залог/риск, техническую совместимость и сетевое разнообразие — и размещение на уровне портфеля вместо одного непрозрачного балла.

Это цели проекта, а не возможности, реализованные в данной alpha-версии s3d. В этом выпуске `s3d` использует политики, предоставленные индексатором; полная система оценки хостов и выбора портфеля внутри `s3d` не реализована.
